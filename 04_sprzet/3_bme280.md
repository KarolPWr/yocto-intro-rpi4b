# Czujnik BME280 po I2C

BME280 mierzy temperaturę, ciśnienie i wilgotność. Rozmawia z procesorem po I2C. Sterownik jest już w kernelu RPi,
więc potrzebujemy trzech rzeczy:
1. włączonej szyny I2C,
2. wpisu w device tree, że pod danym adresem na szynie jest czujnik,
3. testu z userspace.

Ustaw środowisko:

    # kontener
    source /workdir/bitbake-builds/rpi4/build/init-build-env

## Podłączenie

Przy wyłączonym zasilaniu:

| BME280 | Raspberry Pi |
|---|---|
| VIN / VCC | 3V3 (pin 1) |
| GND | GND (pin 9) |
| SCL | GPIO3 / SCL (pin 5) |
| SDA | GPIO2 / SDA (pin 3) |

Piny znajdziesz na schemacie złącza: [RPI_PINOUT.png](../RPI_PINOUT.png).

Zasilanie 3,3 V, nie 5 V. Sprawdź połączenia dwa razy.

## Szyna I2C

Dopisz na końcu fragmentu `~/yocto-kurs/meta-kurs/conf/fragments/kurs.conf`:

    # szyna I2C na pinach GPIO2/GPIO3 + narzędzia (i2cdetect)
    ENABLE_I2C = "1"
    IMAGE_INSTALL:append = " i2c-tools"

Zapisz zmiany w git (na hoście):

    cd ~/yocto-kurs/meta-kurs
    git add .
    git commit -m "kurs.conf: I2C"

Zbuduj obraz i sprawdź, co `ENABLE_I2C` zmienił w `config.txt`:

    # kontener
    bitbake core-image-base
    grep -A 2 I2C /workdir/bitbake-builds/rpi4/build/tmp/deploy/images/raspberrypi4-64/bootfiles/config.txt

Wgraj obraz na kartę tak jak w ćwiczeniu 5 z dnia 1. Na płytce:

    modprobe i2c-dev
    i2cdetect -l
    i2cdetect -y 1

Moduł `i2c-dev` tworzy pliki `/dev/i2c-*`, przez które programy takie jak `i2cdetect` rozmawiają z szyną.
`i2cdetect -y 1` sprawdza po kolei adresy na szynie 1 i pokazuje te, pod którymi coś odpowiedziało.

**Q: Pod jakim adresem jest czujnik?**

## Overlay czujnika

Na I2C nie ma automatycznego wykrywania urządzeń. Kernel nie wie, że pod tym adresem jest BME280, dopóki nie
przeczyta tego w device tree. Sterownik czeka w obrazie jako moduł:

    modinfo bmp280_i2c | grep -i bme280

Tym razem nie piszemy overlaya sami. Kernel Raspberry Pi ma gotowy overlay `i2c-sensor` dla kilkudziesięciu
czujników I2C, w tym BME280. Wszystkie overlaye RPi i ich parametry są opisane w pliku
[README overlayów](https://github.com/raspberrypi/linux/blob/rpi-6.18.y/arch/arm/boot/dts/overlays/README).

Znajdź w nim `i2c-sensor` i ułóż linię `dtoverlay=...` dla BME280 pod adresem, który pokazał `i2cdetect`.

<details>
<summary>Podpowiedź</summary>

    dtoverlay=i2c-sensor,bme280

</details>

### Overlay w obrazie

meta-raspberrypi nie buduje wszystkich overlayów z kernela, tylko te z listy `RPI_KERNEL_DEVICETREE_OVERLAYS`.
Sprawdź, czy jest na niej nasz:

    # kontener
    bitbake-getvar --value RPI_KERNEL_DEVICETREE_OVERLAYS | tr ' ' '\n' | grep i2c

Nie ma. Dopisz go na końcu fragmentu `~/yocto-kurs/meta-kurs/conf/fragments/kurs.conf`:

    # gotowy overlay czujników I2C z kernela RPi (domyślnie meta-raspberrypi go nie buduje)
    RPI_KERNEL_DEVICETREE_OVERLAYS:append = " overlays/i2c-sensor.dtbo"

Overlaye z tej listy buduje recepta kernela. Lista zmienia task `do_compile` kernela, więc bitbake uruchomi go
jeszcze raz:

    # kontener
    bitbake virtual/kernel
    ls /workdir/bitbake-builds/rpi4/build/tmp/deploy/images/raspberrypi4-64/ | grep i2c-sensor

### Szybki test

Overlay sprawdzimy bez flashowania - jak w ćwiczeniu 1. Z hosta:

    scp ~/yocto-kurs/bitbake-builds/rpi4/build/tmp/deploy/images/raspberrypi4-64/i2c-sensor.dtbo root@<ADRES_IP>:/boot/overlays/

Na płytce dopisz do `config.txt` linię `dtoverlay=...` ułożoną z README i zrestartuj:

    echo "<TWOJA LINIA dtoverlay=...>" >> /boot/config.txt
    sync
    reboot

## Test

Na płytce:

    dmesg | grep -i bmp280

`modprobe` nie przetrwał restartu - `i2c-dev` trzeba załadować jeszcze raz:

    modprobe i2c-dev
    i2cdetect -y 1

Pod adresem czujnika jest teraz `UU` - adres zajął sterownik. Overlay dodał do device tree węzeł czujnika:

    find /proc/device-tree/ -name "bme280*"
    cat $(find /proc/device-tree/ -name "bme280*")/compatible

Po napisie `compatible` kernel wybrał sterownik `bmp280_i2c` (porównaj z `modinfo` wyżej).

Czujnik jest urządzeniem w podsystemie IIO (Industrial I/O):

    cat /sys/bus/iio/devices/iio:device*/name

W katalogu urządzenia o nazwie `bme280` (niżej `iio:device0` - u Ciebie numer może być inny):

    cat /sys/bus/iio/devices/iio:device0/in_temp_input
    cat /sys/bus/iio/devices/iio:device0/in_pressure_input
    cat /sys/bus/iio/devices/iio:device0/in_humidityrelative_input

Dotknij czujnika palcem i odczytaj temperaturę jeszcze raz.

## Do obrazu

Linia `dtoverlay=` dla czujnika musi trafić do `config.txt` w obrazie. Dopisz ją w
`~/yocto-kurs/meta-kurs/recipes-bsp/bootfiles/rpi-config_git.bbappend` - tak samo jak linię dla diody.

Pliku `i2c-sensor.dtbo` nie dopisujemy do `IMAGE_BOOT_FILES`. Zbuduj obraz i sprawdź, czy i tak trafi na partycję boot:

    # kontener
    bitbake core-image-base
    tail -n 3 /workdir/bitbake-builds/rpi4/build/tmp/deploy/images/raspberrypi4-64/bootfiles/config.txt
    bitbake-getvar -r core-image-base --value IMAGE_BOOT_FILES | tr ' ' '\n' | grep overlays/


Obraz wgramy w następnym ćwiczeniu. Zapisz zmiany w git (na hoście):

    cd ~/yocto-kurs/meta-kurs
    git add .
    git commit -m "kurs.conf: BME280 na I2C (overlay i2c-sensor)"

## Gdy czujnik nie działa

Sprawdzaj od sprzętu w górę:
1. **Szyna:** `ls /dev/i2c-*` (po `modprobe i2c-dev`), w `/boot/config.txt` jest `dtparam=i2c_arm=on`.
2. **Sprzęt:** `i2cdetect -y 1` - czujnik powinien odpowiedzieć nawet bez sterownika. Nic nie widać - sprawdź
   zasilanie 3,3 V, GND i czy SDA/SCL nie są zamienione.
3. **Device tree:** `find /proc/device-tree/ -name "bme280*"` - brak węzła oznacza, że overlay nie został nałożony
   (plik `/boot/overlays/i2c-sensor.dtbo`, linia w `/boot/config.txt`). Węzeł jest, a w `i2cdetect` nie ma `UU` -
   sprawdź, czy adres w węźle (`bme280@76` / `bme280@77`) zgadza się z tym z `i2cdetect`.
4. **Sterownik:** `lsmod | grep bmp280`, `dmesg | grep -i -E "bmp280|i2c"`.
